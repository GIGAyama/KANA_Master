# KANA_Master
ひらがな・カタカナかきかたマスター

小学1年生が **じぶんから すすんで** ひらがな・カタカナを **ただしく** 身につけるための
学習アプリです。字の形（書字）だけでなく、1年生が いちばん つまずく
**拗音（きゃ）・促音（っ）・長音（おとうさん）・助詞（は・へ・を）** を
「おと（拍）」と「マス（文字）」の関係から 学べるように作ってあります。

インストール不要・登録不要・通信なしで動く PWA です。ブラウザで開けば
そのまま つかえて、記録は 端末の中にだけ 残ります。

# このアプリの 設計

## 1. なにを 身につけるのか（学習モデル）

「もじが 書ける」だけでは 1年生の国語は 終わりません。このアプリは
**4 つの ちから** を それぞれ 別に そだて、別に 記録します
（学習ログの `mode` も この 4 つで 分かれます。§7）。

| ちから | 中身 | どこで やるか | 記録のしかた |
| --- | --- | --- | --- |
| **かく**（書字） | 字の形・かきじゅん・とめはね | 「かく」画面 | 文字ごとの 4 だんかい（`progress`） |
| **よむ**（読字） | もじ ↔ おと ↔ ことば・にた字の見わけ | 「よむ」画面 | ふくしゅうの はこ（`skill`） |
| **ことば**（語彙） | なかまの ことば・はんたいの ことば | 「よむ」画面 | ふくしゅうの はこ（`skill`） |
| **とくべつな おと**（特殊音節） | っ ゃゅょ ん のばす は へ を | 「とくべつ」画面 | ふくしゅうの はこ（`skill`） |

この 4 つは たがいに 代わりが ききません。**書けるのに 読めない／読めるのに
「がっこう」が「がこう」に なる／もじは 読めるのに 文の いみが とれない**
という つまずきは、どれか 1 つしか やっていないと かならず 起きます。

### 「かく」の 4 だんかい

定義は `App.jsx` の `STAGE_INFO` ただ 1 か所です。

| だんかい | 名まえ | 色 | 進みかた |
| --- | --- | --- | --- |
| 一 | かきじゅん | 藍 | 書き順アニメを見る |
| 二 | なぞりがき | 若竹 | お手本を 2 回なぞる |
| 三 | じぶんでかく | 藤 | ガイドなしで 3 回れんぞく正解 |
| 四 | かんぺき（花丸） | 朱 | その文字をつかった ことばを 1 つあつめる |

## 1.5. ことばずかん（`WORD_BANK`）── ことばの データは 1 か所だけ

1年生が 1年かんで 出あう ことばを、**`App.jsx` の `WORD_BANK` /
`WORD_BANK_KATA` ただ 1 か所**に まとめています（ひらがな 561 語・
カタカナ 152 語、あわせて 713 語）。1 語 足すと つぎの ぜんぶが 増えます。

| つかう ところ | どう つかうか |
| --- | --- |
| あたまの おと | 「あ」から はじまる ことばを 索引（`HEAD_WORD_INDEX`）から ひく |
| ことばの なかの もじ／にた もじ さがし | その字を ふくむ ことばを さがす |
| なかまの ことば | `g:`（なかま）が おなじ ものを こたえ、ちがう ものを まちがいに |
| しりとり | コンピュータの 手として つかう |
| ことばあつめの ヒント | 「じぶんで 書ける じ」だけで 作れる ことばを 出す |

1 語は `{ w: 'いぬ', p: 'dog', g: 'animal' }` の 3 つだけです。
`p` は さしえ（`PICTS` のキー）、`g` は なかま（`WORD_GROUPS` のキー）。

### なかま（`WORD_GROUPS`）は 教科書の「なかまの ことば」

からだ／ひと・かぞく／がっこう／べんきょうの どうぐ／たべもの／
やさい・くだもの／どうぶつ／とり／むし／うみの いきもの／はな・き／
てんき・きせつ／しぜん／のりもの／いえ・まち／きるもの／あそび／
うごきの ことば／ようすの ことば／いろ／とき／ばしょ・むき／あいさつ
の 23 なかま（＋出題に つかわない 2 つ）。

**こたえが 2 つに ならないように**、なかまには 2 つの しかけが あります。

| しかけ | 意味 |
| --- | --- |
| `quiz: false` | 「みの まわりの もの」のように 何でも 当てはまる なかまは 出題しない（ことばは つかう） |
| `avoid: [...]` | まちがい選択肢に してはいけない なかま。「どうぶつは どれ？」に「すずめ」を まぜない |
| `text: true` | 絵にできない なかま（うごき・ようす・いろ・とき・ばしょ・あいさつ）。text どうしだけで 出題するので、**さしえの ある／ない が こたえの ヒントに ならない** |

`text: true` の なかま どうしを まぜると、そのまま
「はしる／おおきい／あか／あさ／うえ／ありがとう」から えらぶ、
品詞の 見わけの もんだいに なります。

### はんたいの ことば（`OPPOSITE_PAIRS`）

`['おおきい','ちいさい']` のように 対で 26 組。行き・帰りの 両方向を
出すので 52 もんに なります。まちがい選択肢は ほかの 対から とるので、
「はんたいの いみ」以外の 手がかりでは えらべません。

### ことばを 足すときの きまり

- ひらがなの 表には **ひらがなだけ**、カタカナの 表には **カタカナだけ**
  （`はんズボン` のような まぜ書きは 出題の 形が くずれます）
- カタカナは 小さい **ァィゥェォ を つかわない**（`フォーク` `ソファ` など）。
  1年生の 学習はんいの 外で、拍の かぞえかたも 合わなくなります
- **おなじ ことばを 2 つの なかまに 書かない**（`あめ` ＝ 雨／飴 のように
  まぎれる ものは どちらか 1 つに きめる。飴は `あめだま` にしてあります）

### 「やさしい じゅん」で すすむ

五十音表は「あ」から ならんでいますが、**書きやすさの じゅんでは ありません**
（「あ」は 3 画で むずかしく、「く」「し」「つ」は 1 画です）。
はじめの 1 文字で つまずかせないよう、**すすめる順だけ** を画数のすくない字から
にしています（`LEARN_ORDER_HIRA` / `LEARN_ORDER_KATA`）。
**表の見た目は 教科書どおりの 五十音のまま** です。ここは分けて考えてください。

## 2. とくべつな おと（このアプリの 中心）

1年生の つまずきは 字の形ではなく、**耳できいた おとを かみに書く ところ**
に集まります。そこで「おと（拍）」と「マス（文字）」の関係を、
アプリ全体で **ただ 1 か所の関数** として定義しました。

```js
splitCells('でんしゃ')  // → ['で','ん','し','ゃ']  マスは 4 つ（小さい字も 1 マス）
splitMora ('でんしゃ')  // → ['で','ん','しゃ']     おとは 3 つ
splitMora ('ケーキ')    // → ['ケ','ー','キ']       おとは 3 つ（ー も 1 拍）
```

- 小さい ゃゅょ **だけ**が 前の字と いっしょで 1 つの おと（きゃ ＝ 2 もじ 1 拍）
- 小さい っ・ん・のばす ー は、それぞれ **それだけで 1 つの おと**

のばす「ー」を 前の字に くっつけては いけません。ひらがなの「おとうさん」は
「う」を 1 拍と かぞえるのに、カタカナの「ケーキ」だけ 2 拍に なってしまい、
子どもに 教える きまりが 表と裏で くいちがいます（ケーキ ＝ ●●● で 3 拍）。

画面では マスの下に ドット（●）を出して「**おと 3 つ・マス 4 つ**」と
はっきり見せます（下の MIM の節）。これが 拗音・促音の理解の かなめです。

### 6 つの ユニット（`SPECIAL_UNITS`）

| ユニット | しるし | おぼえること | よくある まちがい |
| --- | --- | --- | --- |
| てん と まる | ゛゜ | 濁点・半濁点で おとが かわる | かき → かぎ、はんだ → ぱんだ |
| はねる おと | ん | 「ん」も 1 つぶんの おと | みかん → みか |
| つまる おと | っ | 小さく書いて いちど とまる | がっこう → **がこう / がつこう** |
| ねじれる おと | ゃゅょ | 2 もじで おとは 1 つ | でんしゃ → **でんしや** |
| のばす おと | ー | ひらがなは う／あ、カタカナは ー | おとうさん → **おとおさん**、こおり → こうり |
| くっつきの ことば | はへを | 「わ・え・お」と読むが「は・へ・を」と書く | わたし**は**、がっこう**へ**、ほん**を** |

ことばの数は てん と まる 24／はねる おと 21／つまる おと 23／
ねじれる おと 23／のばす おと 27 語、くっつきの ことばは 22 文です。

まちがい選択肢は 思いつきではなく、**1年生が じっさいに 書く形** を
ことばごとに `bad:` として 手で持たせています。ここは 教材の質そのものなので、
足すときも「本当に子どもが書く形か」で えらんでください。
（`bad:` を持たない ことばは 出題されません。）

### もんだいの かたち

出題を つくる関数は `18.7. 出題エンジン` の 9 つだけです。

| かたち | 関数 | といかけ | ねらい |
| --- | --- | --- | --- |
| どっちが ただしい？ | `makeSpellingQuestion` | 絵を見て 正しい つづりを えらぶ | まちがい形を はっきり否定する |
| ますに いれよう | `makeFillQuestion` | あいたマスに 入る字を えらぶ | 小さい字の 位置と 有無 |
| おとは いくつ？ | `makeCountQuestion` | 手を たたく かず | 拍の 分解（すべての土台） |
| くっつきの ことば | `makeJoshiQuestion` | 文の あなを うめる | 助詞は 文の中でしか 練習にならない |
| あたまの おと | `makeHeadSoundQuestion` | この もじから はじまる ことばは？ | もじ → おと → ことば |
| ことばの なかの もじ | `makeWordCharQuestion` | ことばの あいた マスに 入る もじは？ | 語の中で 字を とらえる |
| にた もじ さがし | `makeConfuseQuestion` | ことばの まん中の 字を 見わける | ぬ／め、シ／ツ の 弁別 |
| なかまの ことば | `makeGroupQuestion` | たべものは どれ？ | ことばの いみを なかまで つなぐ |
| はんたいの ことば | `makeOppositeQuestion` | 「おおきい」の はんたいは？ | 対に なる いみを つかむ |

「ねじれる おと」には **拗音一覧表**（きゃ〜ぴょ の 33 個）も置いてあります。

## 4. 多層指導モデル MIM を 取り入れる

[多層指導モデル MIM](http://mswwres.meijigakuin.ac.jp/~kaizu/mim/)（海津亜希子）は、
読みの つまずきを **顕在化する前に** つかまえ、子どもごとに 指導の あつさを
かえる モデルです。とくに **特殊音節に 焦点を あてている** 点が、この
アプリの ねらいと そのまま かさなります。取り入れたのは 次の 4 つです。

### ① 視覚化 ── おとを ● で 見せる

目に見えない「おと」を ドットで 見えるようにします（`MimDots`）。

| 見た目 | 意味 |
| --- | --- |
| ● （ぬりつぶし） | ふつうの おと（清音・濁音・半濁音・ん） |
| ○ （小さい・点線） | つまる おと「っ」＝ **音を出さない** ところ |
| ● ＋ 上の かっこ | ねじれる おと「きゃ」＝ 2 もじで ● 1 つ |
| ● ─ ● （よこ線） | のばす おと ＝ まえの おとと つながる |

```
ねこ    ● ●
ねっこ  ● ○ ●
でんしゃ ● ● ●      （マスは 4 つ、おとは 3 つ）
```

マスの 数と おとの 数が **ちがう** ことが 一目で 分かるのが かんじんです。

### ② 動作化 ── 手で リズムを とる

`RhythmPlayer` が 1 拍ずつ ● を ひからせ、手の うごきを 出します。

| おと | 手 | 音 |
| --- | --- | --- |
| ふつう・ん | たたく | 鳴る |
| ねじれる（きゃ） | 2 もじ まとめて 1 かい たたく | 鳴る |
| つまる（っ） | **グーに にぎる** | **鳴らさない** |
| のばす | よこに ひっぱる | 長めに 鳴る |

促音のところで **音を鳴らさない** のが この機能の かなめです。
「聞こえないのに 書く字が ある」ことを、耳と手の りょうほうで つかみます。

### ③ ちからだめし「よみめいじん」（MIM-PM 型）

MIM-PM に ならった **1 分 × 2 = 2 分** の みじかい 課題です（`MimCheckView`）。

| テスト | 内容 | みているちから |
| --- | --- | --- |
| ① えに あう ことば さがし | 絵に合う 正しい つづりを 3 択から えらぶ | 正しい表記を 素早く 見分ける |
| ② 3 つの ことば さがし | つながった かな列を 3 語に 線で わける | まとまりで 読む（流暢性） |

出題は MIM と同じく
**清音 → 濁音・半濁音 → 長音 → 促音 → 拗音 → 拗長音 → カタカナ** を
1 サイクルとして 5 回 くりかえします（`MIM_PM_ITEMS`）。
まちがい選択肢も MIM と同じ考えで、形が にている／濁点の 有無／語順の
入れかえ／音が にている／特殊音節の あやまり から つくっています。

点数そのものより **まえの じぶんと くらべた のび** が大事なので、
結果は かならず 折れ線（`MimHistoryChart`）で 見せます。
2 週間 たつと ホームに もういちど さそいが 出ます。

### ④ 3 つの ステージ（層）で 指導の あつさを かえる

ちからだめしの 結果から、その子に 合う 指導の あつさを きめます（`tierPlan`）。
**MIM の いちばんの 核心は、アセスメントと 指導が つながっていること**なので、
判定して 終わりにせず、出題そのものを 変えています。

| ステージ | 出題数 | つかう ことば | えらぶ かず | ドット | リズム |
| --- | --- | --- | --- | --- | --- |
| 1st（ふつう） | 6 もん | 12 語 | 3 つ | こたえあわせの時だけ | なし |
| 2nd（すこし ていねい） | 5 もん | 4 語 | 2 つ | **つねに 表示** | なし |
| 3rd（とても ていねい） | 4 もん | 2 語 | 2 つ | **つねに 表示** | **毎問 見せる** |

ステージが 上がる（＝手あつくする）ほど、**あつかう ことばを しぼって
おなじ ものを くりかえし**ます。まぐれで 当たる余地を へらし、
できたことが 積みあがるようにするためです。
3rd ステージでは こたえあわせの あとに かならず リズム（動作化）を
はさむので、つぎの もんだいへ すすむ 間も ゆっくりになります。

さかいめは `tierFromScore()` の 2 か所だけです。2 つの課題の 正解数の合計
（1 問 1 点・制限時間つきなので 上限は 決まっていません）で

| 合計 | ステージ |
| --- | --- |
| 12 点以上 | 1st（ふつう） |
| 6〜11 点 | 2nd（すこし ていねい） |
| 5 点以下 | 3rd（とても ていねい） |

ちからだめしを まだ 受けていない子は、ふだんの「とくべつな おと」の
正答ぐあいから おおまかに きめます（`currentTier()`。10 問に とどかない
うちは 1st、正答率 80% 以上で 1st・55% 以上で 2nd・それ未満で 3rd）。

> **ステージの さかいめ（点数）は このアプリ独自の めやす**で、
> MIM-PM の 正式な標準得点では ありません。画面にも そう書いてあります。
> 正式な判定が 必要な場合は、MIM のパッケージと 標準得点表を お使いください。

## 5. 「じぶんから やる」ための しくみ

子どもが 自分から はじめられないのは、たいてい
**「なにを どこまで やれば おわりか」が 見えない** からです。

- **きょうの めあては 毎日 おなじ 3 つだけ**（`MISSIONS`／5 分ていど）
  1. ふくしゅう 6 もん　2. もじを かく 2 かい　3. とくべつな おと 6 もん
- ホームの **いちばん上に来るのは その 3 つとリング表示**。子どもが きめる
  ことは「どれから やるか」だけで、なにを やるかは まよわせない
- 3 つ そろうと **カレンダーに 花丸のはんこ** が おされる（`StampCalendar`）
- **つぎの もじ** はアプリが えらぶ（やさしい じゅんの まだの字）
- 連続日数（ストリーク）・レベル（しょうごう）・ごほうびの はんこ図鑑
  （しょうごうと はんこは ヘッダーの ボタンから）

ホームの ならびは 上から あいさつ → ちからだめしの さそい（あれば）→
**きょうの めあて 3 つ** → つぎの もじ → にがてボックス → すすみぐあい →
はんこカレンダー → 大人向けのまとめ、の順です。

### おうちの方・先生へ

ホームの いちばん下に、たたんである **大人向けのまとめ**（`GuardianPanel`）が
あります。学習日数・自力で書ける文字数・復習まちの数に加えて、
**いま どの単元で つまずいているか** を ことばで出します。
記録は端末内の `localStorage` だけで、どこにも送信しません。

## 7. 学習ログ（共通スキーマ `study.v1`）

GIGA山の学習アプリ 9 本は、学習のたびに **共通の形** のログを端末にためます。
先生は「まなびクエスト」から、9 本ぶんを横断して見られます。
このアプリが出力するスキーマ版は **`study.v1`** です。

| 項目 | 値 |
| --- | --- |
| 保存先 | `localStorage` の **`study.records.v1`**（オリジンは `gigayama.github.io`） |
| `appId` | **`kana-master`** |
| 配布形態 | グローバル（IIFE）。`globalThis.StudyLog` / `globalThis.KanaStudy` |
| 送信 | **アプリは保存のみ。外部送信は一切しません** |
| 個人情報 | 氏名・出席番号などは**持ちません**。だれの記録かは送信ページが付けます |

### `study.records.v1` は このアプリ専用のキーでは ありません

> `study.records.v1` は複数アプリ共通の学習ログです。このアプリ専用のキーではないため、
> リセット処理やクリーンアップの対象に含めないでください。

このアプリのキーは `kkm` 接頭辞で始まります。「さいしょから」（`resetAll`）は
その接頭辞に一致するキーだけを消し、**`study.records.v1` には触れません**。
ここを消すと、児童が学習したきろくが**誰にも気づかれないまま永久に失われます**
（送信ページが送るまで、端末の中にしかないため）。`localStorage.clear()` も禁止です。
Service Worker のキャッシュ掃除も `kkm-` で始まるものだけが対象です。

### 1 レコードの単位（活動 → `mode` / `unit.id`）

このアプリには **たがいに代わりの利かない 4 つのちから** が同居しています。
合算した正答率は「何ができて何ができないか」を打ち消し合い、次の一手が
決まりません。そのため `mode` で分け、`ext.ability` にも同じ値を残します。

| `mode` | 画面・活動 | `unit.id` | 1 レコードの範囲 |
| --- | --- | --- | --- |
| `write` | かく | `kana-{文字}` | 文字を えらんでから 離れるまで（**文字ごと**） |
| `read` | よむ（あたま／ことばの なか／にた もじ） | `read-head` / `read-inword` / `read-confuse` | コース 1 かい |
| `vocab` | なかまの ことば・はんたいの ことば | `vocab-group` / `vocab-opposite` | コース 1 かい |
| `special` | とくべつな おと（6 ユニット） | `special-{key}` | ユニット 1 かい |
| `review` | ぜんぶ まぜて（SRS の期限到来分） | `review-mixed` | コース 1 かい（`source: review`） |
| `mimcheck` | ちからだめし（よみめいじん） | `mim-check` | **課題ごと**（1 ぷん×2 で 2 レコード） |

ホーム・ずかんは学習活動ではないので記録しません。

### 読みちがえを防ぐための約束

- **なぞり書きと自力書きを混ぜない。** `ext.guided` で分け、切りかわった時点で
  レコードも分けます。初回正答（`firstTryCorrect`）は**自力書きだけ**から数えます。
  混ぜると、なぞりを くりかえす児童ほど正答率が高く見えます。
  なぞりの回は「お手本＝こたえが出ている」ので `hint: true` / `firstTry: false` です。
- **MIM の層（`ext.tier`）を必ず残す。** えらぶ かずが 3→2 に減れば、あてずっぽうの
  正答率は 33%→50% に上がります。層を見ずに正答率をならべると、
  **手あつい指導を受けている児童ほど成績がよく見える**逆転が起きます。
- **ちからだめしの点数を、ほかの正答率とならべない。** 制限時間つきの流暢性課題で
  性質がちがいます。前の自分と比べた伸びで見ます。
  ステージの境目は**このアプリ独自の目安であり、MIM-PM の正式な標準得点ではありません**。
- **ひらがなとカタカナを混ぜない。** `ext.kanaMode` で分けます。
- **段階が上がった回（`ext.stageUp`）は段階 2 以上のときだけ。** 段階 1 は
  「かきじゅんアニメを見た」だけで、まだ 1 画も書いていません。アプリの画面でも
  「よくできました」が出るのは段階 2 からで、**先生の集計と画面が別のものを
  指さない**ようにそろえています。
- **`activeMs` の無操作判定は 60 秒（全アプリ共通）。** ここを短くすると、
  このアプリの学習時間だけが系統的に小さく出て、熱心に練習した児童ほど
  時間が短く見えるという逆転が起きます。

### 中断（`status: "aborted"`）

- めあての問題数に届く前に画面を離れたら `aborted`。**中断は事実の記録であって
  評価ではありません**が、「量が多すぎる／難しすぎる」のサインとして意味を持ちます。
- **1 問も解答していない中断は保存しません**（ログ枠 500 件を空レコードで
  埋めないため）。
- 5 分もどらなかった離席は中断とし、**タブを離れた時刻で締めます**
  （待っていた 5 分を学習時間に入れると、全児童の学習時間が水増しされます）。
- Chromebook はメモリ不足やスリープでタブが破棄されるため、`pagehide` で
  かならず確定します。1 年生はタブを閉じる操作が多いので、これが無いと
  記録中のレコードが丸ごと失われます。
- 復帰したら**新しいレコード**を始めます。中断済みのレコードに追記はしません。
- かくモードは書きおえた回だけを記録するため、未着手が残らず つねに `completed` です。

### ファイルと たしかめかた

| ファイル | 役割 |
| --- | --- |
| `studyLog.js` | **全アプリ共通・不変**（ロジック版 1.1）。保存するだけ |
| `studySession.js` | このアプリ固有。何を 1 レコードにするかを決める |
| `tools/check-study.js` | 仕様準拠の自動テスト（Node） |

組み立て関数（`KanaStudy.buildStudyRecord`）は `localStorage` にも DOM にも
触れない**純関数**なので、Node からそのまま呼べます。

```sh
node tools/check-study.js
```

`attempted === items.length`・`activeMs <= elapsedMs`・集計から外すレコードが
分母に入っていないこと・中断と完走の判定・リセットが `study.records.v1` に
触れないことを、ここで見ています。**学習ログはまちがった形でためても
その場では誰も気づけない**（気づくのは学期末に集計が合わないとき）ので、
このアプリをさわったら かならず 走らせてください。

新しい `mode` や `ext` の項目を足すときは、**「この値が明日の指導のどの判断を
変えるか」を 1 文で言えること**を条件にします。言えない項目は入れません。
受信側（`GIGAyama/Gamification` の `manabi-quest/10_studylog.gs`）にも
同じ名前で読む側を用意しないと、届いていても画面には出ません。

# つくりの メモ（さわるまえに読むところ）

## アプリとしてインストール（PWA）

画面右上の「アプリにする」ボタンから追加できます。このボタンは
**スタンドアロン起動中（＝すでにアプリとして開いているとき）以外はつねに表示**
されます。ブラウザがインストールダイアログを出せる状態ならそれを表示し、
出せない場合は端末に合わせた手動の手順を案内します。

- **Chromebook / Chrome（PC）**: アドレスバー右端の「⊕（インストール）」、または
  「⋮」→「キャスト、保存、共有」→「ページをアプリとしてインストール」。
- **Edge**: 「…」→「アプリ」→「このサイトをアプリとしてインストール」。
- **Android Chrome**: 「⋮」→「アプリをインストール」。
- **iPhone / iPad（Safari）**: 共有ボタン →「ホーム画面に追加」。

インストールすると全画面で起動し、一度ひらいた文字は Service Worker の
キャッシュにより、電波がなくても練習できます。
長押しメニューからは 4 つのショートカット（もじをかく／ことばずかん／
とくべつな おと／よむ れんしゅう）で目的の画面に直接入れます
（`manifest.webmanifest` の `shortcuts`。`?view=…` を `App.jsx` が読みます）。

### マニフェストの `id` について（重要）

`manifest.webmanifest` の `id` は **相対パスで書くとオリジンのルートを基準に
解決される**ため、`"id": "./"` は `https://<user>.github.io/` になってしまいます。
同じ GitHub Pages ドメインに別の PWA があると識別子が衝突し、ブラウザが
「もうインストール済み」と誤判定して `beforeinstallprompt` が発火せず、
インストールボタンが出なくなります。

そのためこのアプリは配置パスを含む絶対パス
`"id": "/KANA_Master/"` を明示しています。
**フォークして別のパスに配置する場合は、この値もそのパスに合わせて
書き換えてください**（同一オリジン内で一意であれば OK）。

`scope` と `start_url` も同じ理由で絶対パスに統一しました
（`"start_url": "/KANA_Master/index.html"` / `"scope": "/KANA_Master/"`）。
この 3 つがこのフォルダの外を指していると、Chromebook では
**「このアプリのページが、同じサイトの別のアプリのウィンドウで開いてしまう」**
という取りちがえが起きます。書きかえ忘れには 2 つの網をかけてあります。

- **実行時**：`src/boot.js` が起動時に `manifest.webmanifest` を読みなおし、
  `id` / `scope` / `start_url` が いま置かれている場所から始まっていなければ
  開発者ツールのコンソールに警告を出します
  （CSP が `script-src 'self'` なので、`index.html` にインラインでは書けません）。
- **CI**：`tools/check-project.mjs` の `MANIFEST_ID` ゲートが、
  リポジトリ名の絶対パスになっているかを push の前に見ます。

### 同じドメインに複数アプリを置くときの注意

`https://gigayama.github.io/` には多数のアプリが同居しており、以下は
**サイト全体で共有**されます。アプリごとに必ず名前で区切ってください。

| 共有されるもの | このアプリでの区切り方 |
| --- | --- |
| PWA の識別子 | `manifest.webmanifest` の `id` / `scope` / `start_url`（配置パスの絶対パス） |
| CacheStorage | キャッシュ名を `kkm-` で始める（`sw.js` の `CACHE_PREFIX`） |
| localStorage | キーを `kkm` で始める（`App.jsx` の `STORAGE_PREFIX`） |

そのため次の 2 つは**絶対に書かないでください**。他のアプリのデータまで
消してしまいます。

- `sw.js` の `activate` で、自分のもの以外のキャッシュを削除する
  （`caches.keys()` の結果をそのまま消す）
- `localStorage.clear()`（オリジン全体の保存を消す。リセットは
  `STORAGE_PREFIX` で絞りこんで `removeItem` する）

### 保存しているもの

| キー | 中身 |
| --- | --- |
| `kkm_v3_progress` | 文字ごとの「かく」だんかい |
| `kkm_v4_skill` | ふくしゅうの はこ（よむ・とくべつな おと） |
| `kkm_v4_daylog` | 日ごとの がんばり（はんこカレンダー） |
| `kkm_v4_mim` | ちからだめしの きろく（点数・ステージ） |
| `kkm_v2_words` / `_count` / `_streak` / `_badges` / `_voice` | ことば・練習回数・連続日数・はんこ・音声のオンオフ |
| `kkm_siri_best` | しりとりの最高記録 |
| `kkm_v2_mastered` | 旧データ（読みこみ専用。`kkm_v3_progress` が無いときだけ移行に使う） |

`kkm_v4_*`（`_skill` / `_daylog` / `_mim`）は、ふくしゅうの はこ・はんこカレンダー・
ちからだめしを 足したときに 増えたキーです。**前のバージョンの記録はそのまま
使えます**（`kkm_v3_progress` はそのまま読み、無ければ さらに古い

## 見た目（デザイン）について

「国語の教科書」をイメージした、おちついた紙面にそろえています。

### テーマカラーは朱色（しゅいろ）

先生の赤ペン・朱肉の色である**朱色**が主役です。配色は
**`tailwind.config.js` ただ 1 か所**で定義していて、
Tailwind のクラス（`bg-shu-600` など）として画面じゅうで使えます。
（もとは `index.html` に `tailwind.config = {…}` と書いて CDN 版 Tailwind に
その場で CSS を作らせていました。ビルドする形に変えたときに移しています。）

| 名前 | 意味 | おもな用途 |
| --- | --- | --- |
| `shu` | 朱色 | テーマカラー。見出し・いま選んでいるもの・正解の演出 |
| `sumi` | 墨 | 文字色とニュートラル（すこし温かみのある灰） |
| `washi` | 和紙 | 背景・カードの下地（生成りの紙） |
| `ai` | 藍 | カタカナ・情報（朱の対になる寒色） |
| `midori` | 若竹 | 「できた」をあらわす色（なぞりクリア） |
| `yamabuki` | 山吹 | ごほうび（はんこ・しょうごう） |
| `fuji` | 藤 | 「じぶんでかく」段階 |

キャンバス（お手本・なぞり書きの線）や擬似要素の色だけは Tailwind の外なので、
**`src/extra.css` の `:root` に置いた CSS 変数**（`--kkm-shu` / `--kkm-sumi` /
`--kkm-paper` / `--kkm-rule` / `--kkm-guide` など）から読み出しています
（読み出しは `App.jsx` の `themeColor()` ただ 1 か所）。
**色をかえるときは、`tailwind.config.js` と `src/extra.css` の
この 2 か所だけを直して `npm run build` を走らせてください。**

なお、Tailwind のクラス名を `` `text-${tone}-600` `` のような文字列の
足し算で組み立てると、使われているクラスとして見つけてもらえず色が出ません。
`App.jsx` の `TONES` 表からクラス名を**まるごと**取り出してください。

### 絵文字はつかわない

画面に出る記号は、すべて線だけで描いた SVG アイコンにそろえています。
端末やフォントによって見た目が変わらず、教科書のさしえのように
おちついたトーンでならびます。`App.jsx` に 2 種類あります。

- `SvgIcon` … 操作をあらわす UI アイコン（ボタン・見出し）
- `Pict` / `PICTS` … ことばのさしえ（いぬ・はな・でんしゃ など）

例外はマスコット「えんぴつせんせい」だけで、こちらは絵（`mascot.png` /
`mascot-full.png`）を `MascotFace` / `MascotFull` で出しています。
どちらも もとの絵の たてよこ比のまま表示するので、大きさを変えるときは
`size`（正方形のマスの一辺）や `height`（たかさ）だけを渡してください。

ことばのデータは絵文字ではなく `p: 'dog'` のように `PICTS` のキーを持ちます。
絵文字で保存された古いデータは `EMOJI_TO_PICT` でさしえに読みかえるので、
バージョンアップしても学習記録はそのまま使えます。

#### 子どもに えらばせる さしえは 16 こだけ（`PICT_CHOICES`）

「ことばを つくる」でこどもが選ぶさしえは、`PICTS`（44 種）ぜんぶではなく
**`PICT_CHOICES` の 16 こだけ**です。40 こ並べていたころは、ことばを書くより
「絵さがし」に気もちがいってしまい、そこで手が止まっていました。

- **ぜんぶ 1 画面におさまる数にする**（スクロールさせない）
- **絵の下にことばのラベルを出す**（`たべもの` `どうぶつ` `のりもの` …）。
  絵の意味を当てさせない

この 2 つを守ってください。ふやしたくなったら、まず 1 つ消すこと。
`PICT_CHOICES` にないさしえも、**もんだいのデータや、むかし保存したことばでは
そのまま使えます**（`PICTS` は減らしていません）。この表は「子どもに
えらばせるぶん」だけをしぼったものです。

### 「かんぺき」のしるしは花丸（はなまる）

先生が赤ペンで書いてくれる**花丸**が、このアプリでいちばん大事なしるしです。
`hanamaruPath()` が形を計算でつくる（座標を手で書かない）ので、
花びらの数や大きさを変えても形がくずれません。

おちついた見た目のまま、「おした」「せいかいした」の手ごたえははっきり返します。
定義（`@keyframes` とクラス）は **`src/extra.css` の 1 か所**にまとめてあります。

| クラス | 動き | つかいどころ |

| `kkm-btn` / `kkm-ripple` | しずみこむ＋朱色の波紋 | すべてのボタン |

## 書体（フォント）について

画面に出る文字は **UD デジタル教科書体** にそろえています。
このフォントは Windows 10 以降に標準で入っている Morisawa 社の製品で、
Web フォントとして配布することは許諾されていません。そのため

1. 端末に入っていれば それを使う（`N` / `NK` / `NP`、和名・欧文名・スペース無しの
   別名まで並べて取りこぼさないようにしています）
2. macOS の「游教科書体」
3. どれも無ければ Google Fonts の **Klee One**（教科書体スタイルの楷書）

の順にフォールバックします。

**フォント指定は `src/extra.css` の CSS 変数 `--kkm-font-kyokasho` ただ 1 か所です。**
ここを直せば画面のすべての文字が同じ書体でそろいます。別の場所に書き足さないでください。
（3 のフォールバック先である Klee One の `<link>` だけは `index.html` にあります。
Google Fonts は「見た目だけ」の依存なので、学校でふさがれても字の形が
かわるだけでアプリは動きます。）

なお、**練習キャンバスのお手本はフォントではありません**（下記）。そのため
端末に教科書体が入っているかどうかで お手本の形は変わりません。

また「学習する文字そのもの」を出すところには `.kkm-glyph` クラスを付けています。
教科書体は太さが 1 種類しかなく、`font-black` などで太字を指定すると
ブラウザが線を太らせる合成ボールドになって、とめ・はね・はらいの形が
くずれてしまうためです（`font-synthesis: none` で止めています）。

## お手本は「かきじゅんデータ」から描く

うすいお手本・書き順アニメ・書きはじめの赤い点・自動採点は、**すべて同じ
KanjiVG のストロークデータ 1 つから**作っています（`src/App.jsx` の
`drawKvgStroke()` と `KVG_STROKE_W`）。

**データは リポジトリの中に持っています**（`data/kanjivg-kana.js`・
ひらがな／カタカナ 176 文字・約 50KB）。もとは 使うたびに
`cdn.jsdelivr.net` から とっていましたが、学校のネットワークが そこを
ふさいでいると **お手本も 書き順アニメも なぞり書きも 出ません。**
このアプリの いちばん だいじな機能が、アプリの外の事情で 止まっていました。
取りこみ直しは `npm run kanjivg`。ライセンスは `THIRD-PARTY-NOTICES.md`
（KanjiVG／CC BY-SA 3.0）を見てください。

以前はお手本だけをフォントで描いていました。しかしフォントの字形と KanjiVG
のストロークは**別の書きぶり**なので、

- アニメで見た形と、なぞる形が ちがって見える
- 外形（バウンディングボックス）を合わせても、線の内側の位置までは合わないので、
  赤い点が書きはじめから ずれる
- 端末に教科書体が入っているか（Windows か Chromebook か）で お手本の形が変わる

という問題が残っていました。お手本も同じデータから描くことで、この 3 つが
いちどに解消します。**お手本の描画方法を変えるときは、この「1 つのデータから
描く」という原則を外さないでください。**

線の太さ `KVG_STROKE_W`（109 座標系で 7）は、子どもが書く線の太さ
（マスの 0.07 ＝ 約 7.6）と ほぼ同じにしてあります。ぴったりなぞれると
自分の線がお手本をちょうど おおいかくすので、できたことが目で分かります。

書きはじめの赤い点は `w-5 h-5` の**正方形のいれもの**に `absolute inset-0` で
丸を重ねています。`inline-flex` のままだと行のベースラインぶんだけ
いれものが たてにのび、点が数 px 上にずれます。

## 自動採点について

「じぶんでかく」だんかいでは、書いた線とお手本を くらべて 100 点満点で
採点します（`App.jsx` の `scoreHandwriting`）。

| 観点 | 配点 | 見ているもの |
| --- | --- | --- |
| せんの かたち | 30 | お手本の線と どれだけ重なっているか **← 主役** |
| かきじゅん | 15 | 画の順番 |
| はじめと むき | 15 | 画ごとの書きはじめの位置と向き |
| おおきさ・いち | 20 | 外形の大きさと中心 |
| マスの つかいかた | 10 | マスを 4 等分した部屋の使いぐあい |
| せんの こうさ | 10 | 交わるべき線が交わっているか |

**「せんの かたち」がいちばん大事です。** これが無かったころは、始点・外形・
部屋といった あらい特徴しか見ていなかったため、

- 外形のなかを ぐちゃぐちゃに ぬりつぶす → **90 点（花丸）**
- 下から上へ 逆向きに 書く → **85 点**
- 曲がるところを 直線で ずぼらに書く → **87 点**

と、明らかに書けていないものが高得点になっていました。かたちは
「同じ進みぐあいの場所」どうしを順に くらべるので、逆向き・順番ちがい・
ぐちゃぐちゃは いちどに はじけます（いまはどれも 20〜45 点で不合格）。

かたちが 0.5 に届かないときは、合計におさえ（`gate`）をかけて合格させません。
ほかの観点は あらい特徴しか見ないので、線がまるで違っていても そこそこ
点が入ってしまうためです。ふつうに書けていれば おさえはかかりません。

字ぜんたいが おなじだけ ずれているぶんは、かたちの計算から先に
打ち消します（上限 `SHAPE_SHIFT_CAP`）。位置は『おおきさ・いち』と
『はじめと むき』が すでに見ているので、1 つのミスを 3 回減点しないためです。

**きびしすぎないこと**も大事にしています。1年生らしい ゆるい手ぶれなら

| 書きぶり | 点 |
| --- | --- |
| ほぼお手本どおり | 96〜100（花丸） |
| すこしゆがむ（マスの 5%） | 89〜93（花丸〜◎） |
| かなりゆがむ（マスの 9%） | 80〜85（◎） |
| とてもゆがむ（マスの 13%） | 66〜72（○・合格） |

くらいに収まります。採点の数字（`SHAPE_FREE` / `SHAPE_SPAN` /
`SHAPE_SHIFT_CAP` / `gate`）を変えるときは、**上の「ふつうに書けている側」が
下がりすぎないか**を必ず確かめてください。

## 画面レイアウト

- **たて向き（スマホ・タブレット）**: 練習キャンバスを画面いっぱいに大きく表示。
  文字の表は「もじをえらぶ」ボタンでドロワーとして開きます。
  画面の切りかえは 下のタブでおこないます。
- **よこ向き・PC**: 文字の表と練習キャンバスを左右に並べて表示します。
  画面の切りかえは ヘッダーのタブです。

五十音表には「あ行」「か行」といった**行の見出し**を付けて、教科書と
おなじ かたまりで もじをつかめるようにしています。

## 音声（よみあげ）について

ことばの よみあげは ブラウザの `speechSynthesis` を使いますが、
**日本語の音声が入っていない端末でも すべてのもんだいが とける**ように
作ってあります（もんだいは かならず 絵・ことば・マスの形で 成り立たせ、
音声は そえもの）。Chromebook や 学校端末で 音声が無くても こまりません。
