# hiragana_katakan_kakikatamaster
ひらがな・カタカナかきかたマスター

小学1年生のための、ひらがな・カタカナの かきじゅん れんしゅう＆ことばあつめアプリです。
書き順アニメ・なぞり書き・自動採点で、たのしく文字が身につきます。

## つかいかた

ブラウザで `index.html` をひらくだけで うごきます（ビルド不要）。
GitHub Pages でも公開しています。

## アプリとしてインストール（PWA）

画面右上の「アプリにする」ボタンから追加できます。このボタンは
**スタンドアロン起動中（＝すでにアプリとして開いているとき）以外はつねに表示**
されます。ブラウザがインストールダイアログを出せる状態ならそれを表示し、
出せない場合は端末に合わせた手動の手順を案内します。

- **Chromebook / Chrome（PC）**: アドレスバー右端の「⊕（インストール）」、または
  「⋮」→「キャスト、保存、共有」→「ページをアプリとしてインストール」。
- **Edge**: 「…」→「アプリ」→「このサイトをアプリとしてインストール」。
- **Android Chrome**: 「⋮」→「アプリをインストール」。
- **iPhone / iPad（Safari）**: 共有ボタン →「ホーム画面に追加」。

インストールすると全画面で起動し、一度ひらいた文字は Service Worker の
キャッシュにより、電波がなくても練習できます。

### マニフェストの `id` について（重要）

`manifest.webmanifest` の `id` は **相対パスで書くとオリジンのルートを基準に
解決される**ため、`"id": "./"` は `https://<user>.github.io/` になってしまいます。
同じ GitHub Pages ドメインに別の PWA があると識別子が衝突し、ブラウザが
「もうインストール済み」と誤判定して `beforeinstallprompt` が発火せず、
インストールボタンが出なくなります。

そのためこのアプリは配置パスを含む絶対パス
`"id": "/hiragana_katakan_kakikatamaster/"` を明示しています。
**フォークして別のパスに配置する場合は、この値もそのパスに合わせて
書き換えてください**（同一オリジン内で一意であれば OK）。

`scope` と `start_url` も同じ理由で絶対パスに統一しました。この 3 つが
このフォルダの外を指していると、Chromebook では
**「このアプリのページが、同じサイトの別のアプリのウィンドウで開いてしまう」**
という取りちがえが起きます。書きかえ忘れに気づけるよう、`index.html` に
自己点検スクリプトを入れてあり、ずれている場合は開発者ツールのコンソールに
警告が出ます。

### 同じドメインに複数アプリを置くときの注意

`https://gigayama.github.io/` には多数のアプリが同居しており、以下は
**サイト全体で共有**されます。アプリごとに必ず名前で区切ってください。

| 共有されるもの | このアプリでの区切り方 |
| --- | --- |
| PWA の識別子 | `manifest.webmanifest` の `id` / `scope` / `start_url`（配置パスの絶対パス） |
| CacheStorage | キャッシュ名を `kkm-` で始める（`sw.js` の `CACHE_PREFIX`） |
| localStorage | キーを `kkm` で始める（`App.jsx` の `STORAGE_PREFIX`） |

そのため次の 2 つは**絶対に書かないでください**。他のアプリのデータまで
消してしまいます。

- `sw.js` の `activate` で、自分のもの以外のキャッシュを削除する
  （`caches.keys()` の結果をそのまま消す）
- `localStorage.clear()`（オリジン全体の保存を消す。リセットは
  `STORAGE_PREFIX` で絞りこんで `removeItem` する）

## 見た目（デザイン）について

「国語の教科書」をイメージした、おちついた紙面にそろえています。

### テーマカラーは朱色（しゅいろ）

先生の赤ペン・朱肉の色である**朱色**が主役です。配色は
**`index.html` の `tailwind.config` ただ 1 か所**で定義していて、
Tailwind のクラス（`bg-shu-600` など）として画面じゅうで使えます。

| 名前 | 意味 | おもな用途 |
| --- | --- | --- |
| `shu` | 朱色 | テーマカラー。見出し・いま選んでいるもの・正解の演出 |
| `sumi` | 墨 | 文字色とニュートラル（すこし温かみのある灰） |
| `washi` | 和紙 | 背景・カードの下地（生成りの紙） |
| `ai` | 藍 | カタカナ・情報（朱の対になる寒色） |
| `midori` | 若竹 | 「なぞりクリア」をあらわす色 |
| `yamabuki` | 山吹 | ごほうび（はんこ・しょうごう） |
| `fuji` | 藤 | 「じぶんでかく」段階 |

キャンバス（お手本・なぞり書きの線）の色だけは Tailwind の外なので、
`index.html` の CSS 変数（`--kkm-shu` など）から読み出しています。
**色をかえるときは、この 2 か所だけを直してください。**

なお、Tailwind のクラス名を `` `text-${tone}-600` `` のような文字列の
足し算で組み立てると、使われているクラスとして見つけてもらえず色が出ません。
`App.jsx` の `TONES` 表からクラス名を**まるごと**取り出してください。

### 絵文字はつかわない

画面に出る記号は、すべて線だけで描いた SVG アイコンにそろえています。
端末やフォントによって見た目が変わらず、教科書のさしえのように
おちついたトーンでならびます。`App.jsx` に 2 種類あります。

- `SvgIcon` … 操作をあらわす UI アイコン（ボタン・見出し）
- `Pict` / `PICTS` … ことばのさしえ（いぬ・はな・でんしゃ など）

ことばのデータは絵文字ではなく `p: 'dog'` のように `PICTS` のキーを持ちます。
絵文字で保存された古いデータは `EMOJI_TO_PICT` でさしえに読みかえるので、
バージョンアップしても学習記録はそのまま使えます。

### 「かんぺき」のしるしは花丸（はなまる）

先生が赤ペンで書いてくれる**花丸**が、このアプリでいちばん大事なしるしです。
`hanamaruPath()` が形を計算でつくる（座標を手で書かない）ので、
花びらの数や大きさを変えても形がくずれません。

### アニメーション

おちついた見た目のまま、「おした」「せいかいした」の手ごたえははっきり返します。
定義は `index.html` の 1 か所にまとめてあります。

| クラス | 動き | つかいどころ |
| --- | --- | --- |
| `kkm-btn` / `kkm-ripple` | しずみこむ＋朱色の波紋 | すべてのボタン |
| `kkm-draw` | 線が引かれていく | 花丸・見出しの下線 |
| `kkm-stamp` | はんこをおす | ステージアップ・ごほうび・評価 |
| `kkm-pop-in` / `kkm-rise-in` / `kkm-sheet-up` | あらわれる | モーダル・カード・ドロワー |
| `kkm-shake` | ひとゆすり | かきじゅんをまちがえたとき |
| `kkm-float` / `kkm-breathe` / `kkm-sheen` | ゆらぐ・ひかる | マスコット・かんぺきのもじ |

OS の「動きを減らす」設定（`prefers-reduced-motion`）は
まとめて尊重しているので、個々のアニメーションで気にする必要はありません。

## 書体（フォント）について

画面に出る文字は **UD デジタル教科書体** にそろえています。
このフォントは Windows 10 以降に標準で入っている Morisawa 社の製品で、
Web フォントとして配布することは許諾されていません。そのため

1. 端末に入っていれば それを使う（`N` / `NK` / `NP`、和名・欧文名・スペース無しの
   別名まで並べて取りこぼさないようにしています）
2. macOS の「游教科書体」
3. どれも無ければ Google Fonts の **Klee One**（教科書体スタイルの楷書）

の順にフォールバックします。

**フォント指定は `index.html` の CSS 変数 `--kkm-font-kyokasho` ただ 1 か所です。**
ここを直せば画面のすべての文字が同じ書体でそろいます。別の場所に書き足さないでください。

なお、**練習キャンバスのお手本はフォントではありません**（下記）。そのため
端末に教科書体が入っているかどうかで お手本の形は変わりません。

また「学習する文字そのもの」を出すところには `.kkm-glyph` クラスを付けています。
教科書体は太さが 1 種類しかなく、`font-black` などで太字を指定すると
ブラウザが線を太らせる合成ボールドになって、とめ・はね・はらいの形が
くずれてしまうためです（`font-synthesis: none` で止めています）。

## お手本は「かきじゅんデータ」から描く

うすいお手本・書き順アニメ・書きはじめの赤い点・自動採点は、**すべて同じ
KanjiVG のストロークデータ 1 つから**作っています（`App.jsx` の
`drawKvgStroke()` と `KVG_STROKE_W`）。

以前はお手本だけをフォントで描いていました。しかしフォントの字形と KanjiVG
のストロークは**別の書きぶり**なので、

- アニメで見た形と、なぞる形が ちがって見える
- 外形（バウンディングボックス）を合わせても、線の内側の位置までは合わないので、
  赤い点が書きはじめから ずれる
- 端末に教科書体が入っているか（Windows か Chromebook か）で お手本の形が変わる

という問題が残っていました。お手本も同じデータから描くことで、この 3 つが
いちどに解消します。**お手本の描画方法を変えるときは、この「1 つのデータから
描く」という原則を外さないでください。**

線の太さ `KVG_STROKE_W`（109 座標系で 7）は、子どもが書く線の太さ
（マスの 0.07 ＝ 約 7.6）と ほぼ同じにしてあります。ぴったりなぞれると
自分の線がお手本をちょうど おおいかくすので、できたことが目で分かります。

書きはじめの赤い点は `w-5 h-5` の**正方形のいれもの**に `absolute inset-0` で
丸を重ねています。`inline-flex` のままだと行のベースラインぶんだけ
いれものが たてにのび、点が数 px 上にずれます。

## 学習のながれ（4 だんかい）

1 文字を おぼえるまでの道すじを 4 つに区切り、**画面のどこでも おなじ順番・
おなじ色・おなじしるし**で見せています。定義は `App.jsx` の `STAGE_INFO`
ただ 1 か所です。

| だんかい | 名まえ | 色 | 進みかた |
| --- | --- | --- | --- |
| 一 | かきじゅん | 藍 | 書き順アニメを見る |
| 二 | なぞりがき | 若竹 | お手本を 2 回なぞる |
| 三 | じぶんでかく | 藤 | ガイドなしで 3 回れんぞく正解 |
| 四 | かんぺき（花丸） | 朱 | その文字をつかった ことばを 1 つあつめる |

この 4 だんかいは、練習画面の上の**ステップ表示**（いまどこ／あと何回）と、
五十音表の**マスの色とかどのしるし**の両方に出ます。どちらも `STAGE_INFO` と
`TONES` を見ているので、色や名まえを変えるときは そこだけを直せば
画面ぜんたいが そろって変わります。

## 画面レイアウト

- **たて向き（スマホ・タブレット）**: 練習キャンバスを画面いっぱいに大きく表示。
  文字の表は「もじをえらぶ」ボタンでドロワーとして開きます。
- **よこ向き・PC**: 文字の表と練習キャンバスを左右に並べて表示します。

五十音表には「あ行」「か行」といった**行の見出し**を付けて、教科書と
おなじ かたまりで もじをつかめるようにしています。
