# note 入稿メモ（かきかたマスターの紹介記事）

連載「教室で使えるかもしれないもの作り」向けの紹介記事一式です。

```
docs/note/
├── kana-master-note-article.md   記事本文。そのまま note に貼れる形
├── images/                       実際に操作して撮った26点
└── README.md                     このファイル
```

本文は約 9,000 字（画像の記法を除いた文字数）。画像は 26 点で、本文に出てくる順に
`01` から番号を振ってあります。

---

## 1. 貼るまえに直すところ

**連載番号だけ、こちらでは埋めていません。** タイトル1行目の `#◯` を
実際の番号に書きかえてください。推測で入れると連載の通し番号が壊れるので、
あえて `◯` のまま残しています。

```
# 教室で使えるかもしれないもの作り #◯ 「がっこう」が「がこう」になる。…
```

そのほかは、そのまま貼れる状態です。タイトル案が長いと感じたら、後半の
「おとの かずを 目で かぞえられる」を「おとを 目で かぞえられる」に
縮めても筋は変わりません。

## 2. note に貼る手順

1. `kana-master-note-article.md` の1行目（`# ` から始まる行）を、note の
   タイトル欄に貼ります。`# ` と `#◯` の番号を直すのを忘れないでください。
2. 2行目以降を本文エディタに貼ります。`##` の見出しはそのまま見出しとして
   認識され、note が自動で目次を作ります。
3. 画像は自動では入らないので、`images/` の中を **番号順に手でアップロード**
   します。本文の `![…](images/01-home.png)` の行を、その位置で画像に
   置きかえてください。置きかえたら `![…]` の行は消します。
4. 画像の直後にある1行（「ホーム画面。きょうのめあては…」など）は
   **キャプションです。** note の画像キャプション欄に移して、本文からは
   消してください。本文に残しても読めますが、note では
   キャプション欄のほうが小さく表示されて読みやすくなります。
5. ハッシュタグは `#GIGAスクール` `#小学1年生` `#国語` `#ひらがな`
   `#特殊音節` `#MIM` `#PWA` あたりが本文の内容と合います。

## 5. 撮り直すときの手順

撮影用のスクリプトはリポジトリに残していません（納品前に消しました）。
撮り直すときは、この手順でもう一度組めます。

```bash
npm install
npm run build
node tools/serve.mjs 4180        # 別ターミナル。http://127.0.0.1:4180/KANA_Master/
```

あとは Playwright でシナリオを書いて操作します。踏んだ落とし穴は次の5つです。

1. **もじ表のドロワーが開いたままだと、うしろのボタンを押してしまう。**
   `document.querySelectorAll('button')` の先頭一致で押すと、見えていない
   モーダルのボタンに当たります。`[role="dialog"][aria-label="もじを えらぶ"]`
   の中に絞って押してください。
2. **なぞり書きと自力書きは、かきじゅんデータからマウスで線を引く。**
   `globalThis.KANJIVG_KANA[文字]` の `d` 属性を SVG に入れて
   `getPointAtLength` で点列にし、`canvas.cursor-crosshair` の矩形へ
   換算して `mouse.move` でなぞります。1年生らしい手ぶれは、点列に
   周期の長いサイン波を 1px ほど足すと自然になります。
3. **正しいこたえは DOM に出ていない。** `QuestionCard` の props（`q.answer`）を
   React の内部（`__reactFiber$…` から `memoizedProps`）から読むのが確実です。
   絵をあてずっぽうで押すと、記録画面に出る正答率が不自然になります。
4. **マウスで線を引くと、画面の文字が選択されたまま残る。** 撮る直前に
   `window.getSelection().removeAllRanges()` を呼ばないと、点数の上に
   青い選択の帯が写ります（実際に1枚やり直しました）。
5. **書体は Google Fonts を手もとから返す。** ネットワークが
   `fonts.googleapis.com` に届かないと、教科書体ではなくゴシック体で写ります。
   Playwright の `route` で CSS と woff2 をローカルのファイルから返すと、
   Chromebook で実際に出るのと同じ Klee One になります。アプリ側には
   いっさい手を入れずに済みます。

はんこずかんのボタンだけは、文字ではなくセレクタで押してください。
はんこを1つでも持つとボタンの中に個数が出るので、文字での照合が当たりません
（`button[aria-label*="はんこ"]`。aria-label は「ごほうびの はんこ ずかん を
ひらく」で、あいだに空白が入っています）。

## 6. 文体について踏襲したこと

- 太字・斜体・表・区切り記号（`→` `／` `：` `▲` `▶`）を本文で使っていません。
  Markdown は見出しだけです。
- 箇条書きは手順のところ（導入手順の端末別・使い方のガイド）だけにして、
  ほかは文章で書いています。
- 絵文字は見出しだけです。本文には入れていません。
- 専門用語を日常のことばに置きかえています。デプロイ、ローカルストレージ、
  Service Worker、モーラといった語は出しません。「公開の設定」
  「その端末の中だけに残ります」「おと」と言いかえています。
- 「導入のメリット」は「三つのいいことが期待できます。」から始めて
  「一つ目は」「二つ目は」「三つ目は」でつなぐ型にしました。
- 結びは #9 と同じ「一歩踏み出そうとする先生を、私はいつでも全力で
  応援しています。」です。
- 目玉が既存の見出しに収まらないので、📱 と ✨ のあいだに
  「💡 「おと」と「マス」の ずれを 目で 見せる」と
  「✏️ 採点を 赤ペンで かえす」の2本を足しました（足すのは多くて2本まで）。

### 書き手が足すところ

**教室での出来事は、いっさい書いていません。** これは作者の実践記録ではない
ので、「使ってみたら子どもたちが〜」と書くと嘘になります。書いたのは
「こうなればいいと思って作った」「〜だと思います」までです。

実際の授業でどうだったか、どの子がどこで目を輝かせたかは、ぜひご自身の
ことばで足してください。いちばん効くのはそこだと思います。
入れるなら「💡」の節の終わり（ちからだめしの話のあと）か、
「✨ 導入のメリット」の直前が自然です。
